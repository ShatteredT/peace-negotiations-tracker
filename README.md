# Peacetalk Tracker

Діахронічний аналіз динаміки мирних переговорів Україна–Росія (2022–2026). LLM-агенти (Gemini) оцінюють
новини за шкалою від **−1.0 (ескалація)** до **+1.0 (компроміс)** за чотирма категоріями —
**diplomacy, security, territorial, humanitarian** — а Streamlit-застосунок показує динаміку на графіках
і дає експертам додавати власні замітки з модерацією.

## Поточний стан

| | |
|---|---|
| Джерело корпусу | BBC News Україна (інші джерела — у планах) |
| Відібрано та проаналізовано | 150 статей (26.02.2022 – 23.09.2026) |
| Оцінок у БД | 600 (4 категорії × 150) |
| Agent 1 — Analyst | ✅ готовий |
| Agent 0 — Selector | ✅ готовий (корпус BBC береться з `data/BBC/filtered.json` або з git) |
| Agent 2 — Synthesizer | ✅ резюме й анотації за піврічними періодами (вкладка «Підсумки», маркери на графіку) |
| Автентифікація | навчальні облікові записи без реєстрації (див. «Облікові записи») |
| Модерація заміток (v2.0) | ✅ OFFICIALSTATEMENT очікує рішення Admin; звичайний коментар публікується одразу |
| Сумісність БД | ✅ міграція v1.0 → v2.0 зберігає статті, оцінки, замітки й архівні статуси |
| Демо-деплой | SQLite-знімок у Git, рантайм-копія тимчасова; записані на сайті зміни скидаються після перезапуску |

## Швидкий старт

Усі команди запускаються з кореня проєкту.

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                    # впишіть GEMINI_API_KEY (потрібен лише агентам)

python -m scripts.load_to_db                            # створює data/peacetalk.db з JSON
streamlit run src/ui/app.py
```

## Конвеєр

| Крок | Команда | Результат |
|------|---------|-----------|
| 1. Відбір статей (Selector) | `python -m src.agents.selector_optimized` | `data/filtered_corpus_optimized.json` |
| 2. Аналіз (Analyst) | `python -m src.agents.analyst_agent` | `data/analyzed_articles.json` |
| 3. Завантаження в БД | `python -m scripts.load_to_db` | `data/peacetalk.db` |
| 3a. Резюме (Synthesizer) | `python -m src.agents.synthesizer_agent` | таблиці `period_summaries`, `summary_annotations` |
| 4. Інтерфейс | `streamlit run src/ui/app.py` | — |

Analyst обробляє статті пачками по 15 і підтримує resume: повторний запуск оцінює лише ще не оброблені статті.
Завантажувач ідемпотентний. Якщо в оцінці немає `confidence` (старі дані), у БД пишеться `NULL`, а не вигадане число.
Для другого джерела Selector і Analyst використовують окремі файли корпусу й результатів. Синтезатор зберігає
окреме резюме для кожного джерела й півріччя. На огляді відкрийте вкладку **«Порівняння джерел»**: при виборі
обох джерел графік показує дві незалежні лінії.

### Локальний запуск демо

```powershell
$env:PEACETALK_DEMO_MODE = "true"
.\.venv\Scripts\python.exe -m streamlit run src/ui/app.py
```

Демо використовує санітизовану копію `data/demo/peacetalk_demo.db`; повні тексти статей не включаються.
Щоб відтворити підсумки Радіо Свобода в робочій БД:

```powershell
python -m scripts.load_to_db --db data/peacetalk.db --articles data/filtered_corpus_radio_svoboda_optimized.json --analyses data/analyzed_radio_svoboda_articles.json --agent-version radio-svoboda
python -m src.agents.synthesizer_agent --db data/peacetalk.db --source radio_svoboda --delay 20
python -m scripts.build_demo_db --source data/peacetalk.db --output data/demo/peacetalk_demo.db --overwrite
```

## Агент-Синтезатор

```bash
python -m src.agents.synthesizer_agent                      # резюме для періодів, яких ще немає в БД
python -m src.agents.synthesizer_agent --period 2024-H1     # окремий період (можна кілька разів)
python -m src.agents.synthesizer_agent --source radio_svoboda # резюме лише для одного джерела
python -m src.agents.synthesizer_agent --force              # перегенерувати наявні
python -m src.agents.synthesizer_agent --delay 5            # пауза між періодами, секунд
```

Для кожного піврічного періоду агент отримує оцінки статей і опубліковані експертні замітки та повертає
тенденцію (`escalation / compromise / stable / mixed`), резюме та анотації до двох піків і двох спадів тону.
Піки й спади визначає код, модель лише пояснює їх. Модель задається `SYNTHESIZER_MODEL`
(за замовчуванням `gemini-3.5-flash-lite`). SQLite-схема v3 додає джерело до резюме, анотацій та експертних
заміток; старі записи мігрують із джерелом BBC.

При помилках 503 / 429 запити повторюються з паузою **20 секунд** (до 5 спроб). Збережені пари «джерело/період»
повторно не генеруються, тому після збою достатньо запустити команду ще раз. Схема БД v3 додає джерело до резюме,
анотацій та експертних заміток; старі записи під час міграції отримують джерело BBC.

## Облікові записи (v1.0)

Реєстрація дослідників не входить в обсяг. У сайдбарі обирається один із двох підготовлених
дослідницьких записів. Для переходу в Admin потрібен пароль `PEACETALK_ADMIN_PASSWORD`, заданий
у змінних середовища `.env` або `.streamlit/secrets.toml`; пароль не зберігається в Git. Якщо секрет не задано,
вхід Admin вимкнений.

| Запис | id | Роль | Права |
|---|---|---|---|
| Дослідник А | `analyst_1` | Analyst | створює замітки; редагує й архівує **лише свої** |
| Дослідник Б | `analyst_2` | Analyst | те саме; чужі замітки змінити не може |
| Адміністратор | `admin_1` | Admin | редагує й архівує будь-яку замітку |

Пароль захищає лише демонстраційний режим і не замінює повноцінну автентифікацію. Права на
операції перевіряються в прикладній логіці (`src/ui/app.py`), а не лише приховуванням кнопок.

## Демо-деплой із SQLite

Готова база для демо зберігається як `data/demo/peacetalk_demo.db`; знімок не містить повних
текстів новин. Щоб перебудувати його з локальної БД v2.0 (включно з демонстраційними замітками):

```bash
python -m scripts.build_demo_db
```

Перед генерацією знімок v2.0 має бути актуальним; повні тексти новин будуть видалені лише з demo-копії.
Скрипт не перезаписує наявний файл за замовчуванням. Для свідомого оновлення того самого файла:

```bash
python -m scripts.build_demo_db --overwrite
```

Перевірте створений знімок і зафіксуйте окремим комітом після генерації.
У Streamlit Community Cloud додайте в **App settings → Secrets**:

```toml
PEACETALK_DEMO_MODE = "true"
PEACETALK_ADMIN_PASSWORD = "встановіть-довгий-випадковий-пароль"
```
Також можна задати пароль у змінних середовища `.env` або `.streamlit/secrets.toml`.

У демо-режимі застосунок копіює відстежуваний знімок у тимчасову системну папку й працює з
копією. Це дозволяє SQLite записувати замітки протягом роботи процесу, але вони не є постійними:
після перезапуску або нового деплою початковий знімок відновлюється. Не використовуйте цей режим
для даних, які потрібно зберігати. Локально демо-режим за замовчуванням вимкнений і застосунок
працює з `data/peacetalk.db`.

## Експертні замітки: життєвий цикл і помилки

`PUBLISHED` → `ARCHIVED` (архівація знімає замітку з графіка й звільняє «слот»). Правило домену:
одна **активна** замітка на автора, дату й категорію (унікальний частковий індекс у БД, тому два
паралельні запити не створять дубль).

У v2.0 звичайний тип `COMMENT` одразу має `review_status = APPROVED`. Тип `OFFICIALSTATEMENT`
створюється з `PENDING_APPROVAL`: його не видно на графіку й у загальному списку до рішення
адміністратора. Admin може схвалити (`APPROVED`) або відхилити (`REJECTED`) лише замітку, що
очікує розгляду. Міграція старих заміток зберігає їхній `status` (`PUBLISHED` або `ARCHIVED`) і
позначає їх як `APPROVED` без ретроспективної модерації.

### Міграція наявної БД v1.0 → v2.0

Перед міграцією зробіть резервну копію `data/peacetalk.db`. Для явного запуску:

```bash
python -m scripts.migrate_v2
```

Скрипт додає до `expert_notes` колонки `review_status`, `reviewed_by`, `reviewed_at` і встановлює
`PRAGMA user_version = 2`. Він ідемпотентний; старі статті, оцінки, тексти й часові мітки не
перезаписуються. `python -m scripts.load_to_db` також безпечно викликає ініціалізацію схеми й
автоматично мігрує наявну таблицю v1.0 перед завантаженням.

| Помилка | Коли | Показується як |
|---|---|---|
| `ValidationError` | порожній текст, невідома категорія, дата поза діапазоном | попередження |
| `ConflictError` | слот зайнятий, замітка вже в архіві | попередження |
| `AccessDenied` | спроба змінити чужу замітку | попередження |
| `NotFoundError` | замітки не існує | попередження |
| `TechnicalFailure` | БД недоступна, пошкоджений файл | помилка з кодом `request_id` |

## Час і дати

* Часові мітки (`created_at`, `updated_at`, журнал) зберігаються й показуються в **UTC**,
  формат ISO 8601 із суфіксом `Z`: `2026-10-10T12:00:00Z`.
* `event_date` — календарна дата події без часу (`РРРР-ММ-ДД`), допустимий діапазон від 24.02.2022
  до поточної дати за UTC.

## Спостереження (журнал і метрики)

Кожна операція з замітками та перевірка БД пишуть рядок у `logs/ops.jsonl`: час, операція,
результат (`ok` / `rejected` / `error`), клас помилки, тривалість, `request_id`. Текст заміток у
журнал не потрапляє.

```bash
python -m scripts.ops_report               # кількість успіхів/відмов/збоїв, p50/p95/max
python -m scripts.ops_report --probe       # + перевірка доступності БД
```

Правило сповіщення: **ALERT**, якщо технічних збоїв ≥ 3 за 5 хвилин (код завершення 2).
Як простежити збій: при технічній помилці UI показує `Код для пошуку в журналі: <request_id>`;
знайдіть цей код у `logs/ops.jsonl`. Шлях до БД можна перевизначити змінною `PEACETALK_DB`,
шлях до журналу — `OPS_LOG_PATH`.

## Тести та CI

```bash
python -m pytest
flake8 src/ tests/ --select=E9,F63,F7,F82
```

Тести працюють з тимчасовою БД і не потребують ключа API чи заздалегідь створеної `data/peacetalk.db`.
Вони перевіряють правила домену, права, паралельні запити на один слот, повну міграцію даних v1.0
у v2.0 (включно з ідемпотентним повторним запуском) і наскрізний сценарій
«створити → переглянути → архівувати» через інтерфейс.
