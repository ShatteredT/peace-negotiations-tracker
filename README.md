# Peacetalk Tracker

Діахронічний аналіз динаміки мирних переговорів Україна–Росія (2022–2026). LLM-агенти (Gemini) оцінюють
новини за шкалою від **−1.0 (ескалація)** до **+1.0 (компроміс)** за чотирма категоріями —
**diplomacy, security, territorial, humanitarian** — а Streamlit-застосунок показує динаміку на графіках
і дає експертам додавати власні замітки з модерацією.

## Поточний стан

| | |
|---|---|
| Джерело корпусу | BBC News Україна (інші джерела — у планах) |
| Відібрано та проаналізовано | 150 статей (26.02.2022 – 23.09.2026) |
| Оцінок у БД | 600 (4 категорії × 150) |
| Agent 1 — Analyst | ✅ готовий |
| Agent 0 — Selector | ✅ готовий (корпус BBC береться з `data/BBC/filtered.json` або з git) |
| Agent 2 — Synthesizer | ⏳ не реалізований (вкладка «Підсумки» — статистичне зведення без LLM) |
| Автентифікація | навчальні облікові записи без реєстрації (див. «Облікові записи») |
| Модерація заміток | ⏳ запланована на v2.0 (PT-60, PT-43); у v1.0 замітки публікуються одразу |

## Швидкий старт

Усі команди запускаються з кореня проєкту.

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                    # впишіть GEMINI_API_KEY (потрібен лише агентам)

python -m scripts.load_to_db                            # створює data/peacetalk.db з JSON
streamlit run src/ui/app.py
```

## Конвеєр

| Крок | Команда | Результат |
|------|---------|-----------|
| 1. Відбір статей (Selector) | `python -m src.agents.selector_optimized` | `data/filtered_corpus_optimized.json` |
| 2. Аналіз (Analyst) | `python -m src.agents.analyst_agent` | `data/analyzed_articles.json` |
| 3. Завантаження в БД | `python -m scripts.load_to_db` | `data/peacetalk.db` |
| 4. Інтерфейс | `streamlit run src/ui/app.py` | — |

Analyst обробляє статті пачками по 15 і підтримує resume: повторний запуск оцінює лише ще не оброблені статті.
Завантажувач ідемпотентний. Якщо в оцінці немає `confidence` (старі дані), у БД пишеться `NULL`, а не вигадане число.

## Облікові записи (v1.0)

Реєстрація й паролі не входять в обсяг. У сайдбарі обирається один із підготовлених записів:

| Запис | id | Роль | Права |
|---|---|---|---|
| Дослідник А | `analyst_1` | Analyst | створює замітки; редагує й архівує **лише свої** |
| Дослідник Б | `analyst_2` | Analyst | те саме; чужі замітки змінити не може |
| Адміністратор | `admin_1` | Admin | редагує й архівує будь-яку замітку |

Права перевіряються в прикладній логіці (`src/ui/app.py`), а не лише приховуванням кнопок.

## Експертні замітки: життєвий цикл і помилки

`PUBLISHED` → `ARCHIVED` (архівація знімає замітку з графіка й звільняє «слот»). Правило домену:
одна **активна** замітка на автора, дату й категорію (унікальний частковий індекс у БД, тому два
паралельні запити не створять дубль).

| Помилка | Коли | Показується як |
|---|---|---|
| `ValidationError` | порожній текст, невідома категорія, дата поза діапазоном | попередження |
| `ConflictError` | слот зайнятий, замітка вже в архіві | попередження |
| `AccessDenied` | спроба змінити чужу замітку | попередження |
| `NotFoundError` | замітки не існує | попередження |
| `TechnicalFailure` | БД недоступна, пошкоджений файл | помилка з кодом `request_id` |

## Час і дати

* Часові мітки (`created_at`, `updated_at`, журнал) зберігаються й показуються в **UTC**,
  формат ISO 8601 із суфіксом `Z`: `2026-10-10T12:00:00Z`.
* `event_date` — календарна дата події без часу (`РРРР-ММ-ДД`), допустимий діапазон від 24.02.2022
  до поточної дати за UTC.

## Спостереження (журнал і метрики)

Кожна операція з замітками та перевірка БД пишуть рядок у `logs/ops.jsonl`: час, операція,
результат (`ok` / `rejected` / `error`), клас помилки, тривалість, `request_id`. Текст заміток у
журнал не потрапляє.

```bash
python -m scripts.ops_report               # кількість успіхів/відмов/збоїв, p50/p95/max
python -m scripts.ops_report --probe       # + перевірка доступності БД
```

Правило сповіщення: **ALERT**, якщо технічних збоїв ≥ 3 за 5 хвилин (код завершення 2).
Як простежити збій: при технічній помилці UI показує `Код для пошуку в журналі: <request_id>`;
знайдіть цей код у `logs/ops.jsonl`. Шлях до БД можна перевизначити змінною `PEACETALK_DB`,
шлях до журналу — `OPS_LOG_PATH`.

## Налаштування (.env)

| Змінна | Призначення |
|--------|-------------|
| `GEMINI_API_KEY` | ключ Google AI Studio (лише для Selector/Analyst) |
| `ANALYST_MODEL` | модель Analyst (за замовчуванням `gemini-3.5-flash-lite`) |
| `SELECTOR_MODEL` | модель Selector (за замовчуванням `gemini-3.8-flash`) |

## Тести та CI

```bash
python -m pytest
flake8 src/ tests/ --select=E9,F63,F7,F82
```

Тести працюють з тимчасовою БД і не потребують ключа API чи заздалегідь створеної `data/peacetalk.db`.
Вони охоплюють правила домену, права, паралельні запити на один слот і наскрізний сценарій
«створити → переглянути → архівувати» через інтерфейс.

> Якщо схема БД змінилась (наприклад, після оновлення до v1.0), перейменуйте стару `data/peacetalk.db`
> і виконайте `python -m scripts.load_to_db`.

## ⚠️ Дані поза git

Папки `data/`, `info/`, `helpers/` та `*.db` у `.gitignore`: git їх **не зберігає**. Робіть окремі резервні копії
(результати Gemini коштують квоти). Правила для агентів — у `AGENTS_RULES.md`.
