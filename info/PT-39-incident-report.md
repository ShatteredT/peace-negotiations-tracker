# PT-37–PT-40: навчальний інцидент SQLite

**Статус:** симуляцію виконано в ізольованій навчальній гілці
**Гілка:** `exercise/incident-simulation`
**Вплив на production:** відсутній. Не змінювали `main`, tracked SQLite snapshot або локальну робочу БД.

## Сценарій

Симулювали пошкодження runtime-копії SQLite після її створення. Це не повна база з текстами статей:
у вправі використано disposable-копію демо-знімка/тестову SQLite-БД. GitHub snapshot лишався
недоторканим. Такий сценарій відповідає PT-38 і перевіряє, чи можна повернути runtime-БД до
перевіреного стану з резервної копії.

## Симптоми

- Початковий регресійний тест перевірив, що перед запуском UI створюється перевірений backup.
- До виправлення backup-файлу не було: тест упав з `assert 0 == 1`.
- У симуляції runtime-файл замінили некоректними байтами; SQLite `PRAGMA integrity_check`
  завершився `DatabaseError`, тобто файл не можна безпечно використовувати.

## Гіпотези

1. **Пошкоджений файл SQLite.** Перевірка цілісності помиляється на відомому runtime-шляху.
2. **Неправильний шлях/конфігурація БД.** `PEACETALK_DB` указує на інший або порожній файл, у
   якому немає очікуваної схеми/даних.

У тесті шлях до runtime-БД і тестові дані були відомі наперед. Помилка відтворилася саме під час
перевірки цілісності цього файла; контрольна backup-копія лишилася читабельною. Це підтвердило
першу гіпотезу для симульованого випадку.

## Відновлення та коригувальні дії

- Перед підготовкою UI створюється SQLite backup через SQLite backup API, а не файлове копіювання
  відкритої БД.
- Перед збереженням backup перевіряється `PRAGMA integrity_check`; backup створюється тимчасово,
  перевіряється і атомарно переміщується на місце.
- Для відновлення перевірена backup-БД копіюється у staging-файл, ще раз перевіряється, після чого
  атомарно замінює пошкоджену runtime-БД.
- Тест підтверджує цілісність і наявність початкових даних після відновлення.
- Для демо runtime-копія і її backup живуть у тимчасовому каталозі; tracked snapshot не змінюється.
- CI тепер запускається на push у `exercise/**`, тож результати red/green симуляцій видимі в GitHub.

## Результат

Симульоване пошкодження виявлено, відновлення з backup перевірене. Інцидент не відтворювався на
живому Streamlit deployment і не змінював production-дані. Цей звіт призначено для перенесення в
Confluence у межах PT-39.
